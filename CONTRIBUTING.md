# Contributing to Hyperlattice

## Write an issue

Use a title that names the behavior or improvement. For a bug, state what you expected, what happened, and the shortest way to reproduce it. For a proposal, describe the problem and what would count as done. Include repository and commit details when reporting across projects. Keep secrets and private data out of examples and logs.

## Write a pull request

Give reviewers a short summary of the change and why it matters. Link the issue when there is one. Include the checks you actually ran and their outcomes. If a check was skipped, say so. Keep unrelated changes in separate pull requests when practical.

For performance changes, compare against a named baseline on the same hardware and workload. Report the metric with units, the relevant settings and repeats, and how you checked correctness. Link raw measurements or profiler traces when available.
